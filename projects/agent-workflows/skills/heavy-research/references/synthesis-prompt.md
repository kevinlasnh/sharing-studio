# Main Agent 综合摘要模板

3 个 subagent 返回各自摘要后，main agent 按此模板综合成一份统一摘要展示给用户。

---

## 综合步骤

1. 读取 `<SESSION_DIR>/research/` 下的 3 份 md 文件（web.md / source.md / memory.md）
2. 按子问题编号对齐：同一编号的 3 个维度结论放在一起
3. 标注每条信息的来源维度
4. 识别并显式标出跨维度冲突
5. 输出统一摘要到 terminal（不写文件）

---

## 输出格式

```markdown
## 调研摘要：<主题>

### 子问题 1：<子问题描述>
- <结论 A> [网络·confirmed]
- <结论 B> [源码]
- ⚠️ CONFLICT：网络说 X，源码显示 Y，记忆无相关记录

### 子问题 2：<子问题描述>
- <结论 C> [网络·confirmed]
- <结论 D> [记忆·ByteRover，记录于 YYYY-MM-DD]

...

### 未覆盖子问题
- 子问题 #N：所有维度均无结果（建议：调整调研方向或接受信息缺口）

### 覆盖率总览
| 维度 | 已覆盖 | 总计 | 未覆盖原因 |
|------|--------|------|-----------|
| 联网 | X | Y | ... |
| 源码 | X | Y | ... |
| 记忆 | X | Y | ... |
```

---

## 来源维度标注规则

| 标注 | 含义 |
|------|------|
| `[网络·confirmed]` | 联网维度，2个以上来源印证 |
| `[网络·unverified]` | 联网维度，仅1个来源 |
| `[源码]` | 本地源码维度 |
| `[记忆·ByteRover]` | ByteRover 长期记忆 |
| `[记忆·findings]` | findings.md 短期记忆 |
| `⚠️ CONFLICT` | 跨维度或同维度内部矛盾，不自行裁决 |

---

## 展示给用户后的交互

摘要输出完毕后，询问用户：

> 以上是本轮调研摘要。请问：
> 1. 方案合理 → 我将基于此摘要写 deployment-plan
> 2. 方案不合理 → 请告诉我哪里有问题，我们回到需求澄清阶段重新讨论
