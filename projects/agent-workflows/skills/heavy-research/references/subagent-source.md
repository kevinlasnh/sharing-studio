# 源码 Subagent 专项强化

加载此文件前，先加载 `research-loop-core.md`。本文件是源码维度的 3 个专项强化，叠加在 6+3 基础上。

## 工具

Grep + Read + Glob

---

## 专项强化 4：入口点优先策略

不从随机文件开始扫描，而是先定位入口点，再沿调用链向下追踪：

**入口点定位顺序**：
1. 配置文件（package.json / Cargo.toml / pyproject.toml / go.mod 等）→ 了解项目结构和依赖
2. 主入口文件（main.* / index.* / app.* / server.*）→ 了解启动流程
3. 与调研主题直接相关的文件名（用 Glob 模式匹配 + Grep 关键词定位）

从入口点出发，沿调用链向下追踪，而不是全量扫描所有文件。

---

## 专项强化 5：依赖图双向追踪

找到目标符号（函数 / 类 / 变量）后，双向追踪：

**向上追踪（callers）**：
- Grep 搜索该符号名在其他文件中的引用
- 理解使用场景：谁在什么情况下调用它

**向下追踪（callees）**：
- 读取该符号的实现，找出它调用的其他符号
- 理解实现依赖：它依赖哪些模块 / 外部服务

追踪深度：最多 2 层（避免无限展开）。发现关键依赖时可选择性深入 1 层。

---

## 专项强化 6：覆盖率跟踪

维护一个已读文件清单（在 scratchpad 中记录）：

```
已读文件：
- src/main.ts（入口点）
- src/auth/handler.ts（目标模块）
- src/auth/middleware.ts（callee）
```

每轮检索后更新清单，用于：
- 避免重复读同一文件（节省 tool call 预算）
- 确认相关模块是否都已覆盖
- 作为终止判据之一：相关模块覆盖率达到阈值

**覆盖率阈值**：调研提纲中涉及的所有模块都至少读过一次，且关键路径（入口 → 目标 → 主要依赖）已完整追踪。

---

## 注意事项

- 优先读文件的关键部分（函数签名、类定义、导出接口），而不是全文
- 遇到大文件（>300 行）先读头部和导出部分，再按需读具体实现
- 注释和文档字符串是重要信息来源，不要跳过
