# Main Agent 审查综合模板

2 个 review subagent 返回 Done 后，main agent 按此模板综合成统一审查报告。

---

## 综合步骤

1. 读取 `<SESSION_DIR>/review/` 下的 2 份 md 文件（web.md / source.md）
2. 按审查项编号对齐：同一编号的 2 个维度发现放在一起
3. 标注每条发现的来源维度
4. 按严重度排序：HIGH → MED → LOW
5. 输出统一审查报告到 terminal（不写文件）

---

## 输出格式

```markdown
## 审查报告：<plan 主题>

### 🔴 HIGH 严重度问题

#### 审查项 #1：<原文>
- 发现：<问题描述> [网络]
  - 证据：<...>
  - 建议修复：<具体修改>
- 发现：<问题描述> [源码]
  - 证据：<...>
  - 建议修复：<具体修改>

### 🟡 MED 严重度问题
（同上结构）

### 🟢 LOW 严重度问题
（同上结构）

### ✅ 通过项总览
- 审查项 #N：所有维度均通过

### 修复方案汇总
按修复落点分组（前置检查 / 执行步骤 / 回滚方案 / 风险清单）：
- 在「执行步骤 #2」前增加：<...>
- 在「回滚方案」中补充：<...>
- ...
```

---

## 来源维度标注规则

| 标注 | 含义 |
|------|------|
| `[网络]` | 联网维度发现 |
| `[源码]` | 本地源码维度发现 |
| `[网络+源码]` | 两个维度都发现的同一问题 |
| `⚠️ CONFLICT` | 两维度对同一审查项给出矛盾结论 |

---

## 展示给用户后的交互

报告输出完毕后，询问用户：

> 以上是审查结果与修复方案。请问：
> 1. **修复方案合理** → 我将把修复 inline 改进 deployment-plan.md
> 2. **修复方案不合理** → 请告诉我哪里有问题或想着重审查哪个方向
